# Учёт сборок и деталей

Небольшое веб-приложение для планирования производства: ведёт список деталей, список сборок с планом выпуска и состав (спецификацию) каждой сборки, а затем автоматически считает, сколько деталей нужно изготовить.

Интерфейс сделан на [NiceGUI](https://nicegui.io/), данные хранятся в локальной базе SQLite через [SQLAlchemy](https://www.sqlalchemy.org/). Внешний сервер или установка СУБД не требуются.

---

## Возможности

- **Детали** — добавление, редактирование и удаление, учёт фактически изготовленного количества.
- **Сборки** — план выпуска и количество уже собранных изделий, расчёт остатка.
- **Состав сборок** — какая деталь и в каком количестве входит в каждую сборку.
- **Автоматические расчёты** на вкладке «Детали»:
  - `Нужно всего` — потребность по плану всех сборок;
  - `На несобранные` — потребность только на ещё не собранные изделия;
  - `Осталось` — сколько деталей ещё предстоит изготовить;
  - `Статус` — «Готово» или «В работе».
- **Валидация ввода**: непустые и уникальные названия, неотрицательные количества, «собрано» не может превышать план, количество в составе сборки не меньше 1.
- **Удаление с подтверждением**: при удалении детали приложение предупреждает, в сколько сборок она входит; при удалении сборки её состав удаляется каскадом.
- **Экспорт в Google Таблицы** — одна кнопка переносит все данные (детали, сборки, состав) в облачную таблицу и показывает ссылку на неё.

## Требования

- Python **3.10** или новее (используется синтаксис типизации `Mapped[int]`)
- ОС: Windows, macOS или Linux
- Современный браузер (Chrome, Firefox, Edge, Safari)

Проверить версию Python:

```bash
python --version
```

## Установка окружения

### 1. Положите файл приложения в отдельную папку

```
my-app/
└── app.py
```

Перейдите в эту папку:

```bash
cd my-app
```

### 2. Создайте виртуальное окружение

**Linux / macOS:**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

**Windows (PowerShell):**

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

**Windows (cmd):**

```cmd
python -m venv .venv
.venv\Scripts\activate.bat
```

После активации в начале строки терминала появится префикс `(.venv)`.

> Если в PowerShell активация запрещена политикой выполнения, один раз выполните:
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

### 3. Установите зависимости

```bash
pip install --upgrade pip
pip install nicegui sqlalchemy
```

Либо через файл зависимостей — создайте `requirements.txt`:

```
nicegui>=3.0.4,<4.0
sqlalchemy>=2.0,<3.0
gspread>=6.0
google-auth>=2.28
```

и установите:

```bash
pip install -r requirements.txt
```

## Запуск

```bash
python app.py
```

Приложение само откроет браузер. Если этого не произошло, перейдите вручную:

```
http://localhost:8080
```

Для остановки нажмите `Ctrl+C` в терминале.

### Изменение порта или доступ из локальной сети

В конце файла `app.py` найдите строку:

```python
ui.run(title='Сборки и детали', reload=False)
```

и дополните её нужными параметрами:

```python
ui.run(title='Сборки и детали', reload=False,
       host='0.0.0.0',   # доступ с других устройств в сети
       port=8081,        # другой порт
       show=False)       # не открывать браузер автоматически
```

При `host='0.0.0.0'` приложение будет доступно коллегам по адресу `http://<IP-вашего-компьютера>:8081`. Учтите, что авторизации в приложении нет — используйте это только в доверенной сети.

## Данные

При первом запуске рядом с `app.py` создаётся файл базы данных:

```
assemblies.db
```

- **Резервная копия** — просто скопируйте этот файл.
- **Сброс данных** — остановите приложение и удалите `assemblies.db`; при следующем запуске база создастся заново, пустой.
- **Перенос на другой компьютер** — скопируйте `app.py` и `assemblies.db` в одну папку.

## Экспорт в Google Таблицы

В шапке приложения есть кнопка **«Выгрузить в Google Таблицы»**. Она переносит все три таблицы — «Детали», «Сборки» и «Состав сборок» — в облачную Google-таблицу и показывает ссылку на неё. Если таблицы ещё нет, она создаётся автоматически. Повторная выгрузка полностью перезаписывает данные: листы очищаются и заполняются заново, заголовки первой строки выделяются жирным.

Экспорт работает через **сервисный аккаунт** — отдельную техническую «учётную запись» Google. Настройка нужна один раз.

### Настройка (один раз)

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект (или выберите существующий).
2. Включите два API: **Google Sheets API** и **Google Drive API** — «APIs & Services» → «Enabled APIs & Services» → найти и включить.
3. Создайте сервисный аккаунт: «APIs & Services» → «Credentials» → «Create Credentials» → «Service Account».
4. Откройте созданный аккаунт → вкладка «Keys» → «Add Key» → «Create new key» → формат **JSON**.
5. Скачанный файл переименуйте в `credentials.json` и положите рядом с `app.py`.
6. Убедитесь, что установлены зависимости `gspread` и `google-auth` (см. раздел «Установка окружения»).

> ⚠️ JSON-файл ключа — это пароль от вашей таблицы. Не публикуйте его и не добавляйте в git (он уже есть в `.gitignore`).

### Переменные окружения (опционально)

По умолчанию ничего настраивать не нужно, но поведение можно менять:

| Переменная | Значение по умолчанию | Что меняет |
|---|---|---|
| `GOOGLE_CREDENTIALS` | `credentials.json` | путь к файлу ключа сервисного аккаунта |
| `GOOGLE_SHEET_NAME` | `Учёт сборок и деталей` | название Google-таблицы |
| `GOOGLE_SHARE_EMAIL` | — (не задана) | ваш Gmail: новая таблица будет автоматически расшарена на редактирование |

Пример запуска с доступом к таблице (Linux/macOS):

```bash
export GOOGLE_SHARE_EMAIL="you@gmail.com"
python app.py
```

Windows (cmd):

```cmd
set GOOGLE_SHARE_EMAIL=you@gmail.com
python app.py
```

### Доступ к таблице

Таблица создаётся на сервисном аккаунте, поэтому по умолчанию она видна только ему. Чтобы видеть её самому, есть три пути:

- задать `GOOGLE_SHARE_EMAIL` — тогда при **первом** создании таблица расшарится на ваш Gmail;
- вручную расшарить таблицу: в Google Таблицах «Настройки доступа» → добавить e-mail сервисного аккаунта (поле `client_email` в `credentials.json`) как редактора;
- открыть таблицу по ссылке из приложения и запросить доступ.

> Внимание: `GOOGLE_SHARE_EMAIL` срабатывает только при создании новой таблицы. Если таблица уже существует, доступ нужно выдать вручную.

## Как пользоваться

1. **Вкладка «Детали»** — нажмите `+ Деталь` и добавьте все нужные детали. Поле «Изготовлено» можно пока оставить нулём.
2. **Вкладка «Сборки»** — нажмите `+ Сборка`, укажите название и план выпуска в штуках.
3. **Вкладка «Состав сборок»** — раскройте нужную сборку, выберите деталь, укажите, сколько штук входит в одно изделие, и нажмите «Добавить». Повторная добавка той же детали обновит количество.
4. Вернитесь на вкладку **«Детали»** — потребность и остаток уже пересчитаны.
5. По мере работы вносите факт: в детали — сколько изготовлено, в сборке — сколько собрано. Статусы обновятся автоматически.

Редактирование — клик по строке таблицы. Кнопка «Удалить» находится внутри диалога редактирования.

## Возможные проблемы

| Симптом | Решение |
|---|---|
| `ModuleNotFoundError: No module named 'nicegui'` | Не активировано виртуальное окружение или не установлены зависимости — повторите шаги 2–3 |
| `TypeError` при старте, связанный с `Mapped` | Версия Python ниже 3.10 либо SQLAlchemy ниже 2.0 — обновите: `pip install -U sqlalchemy` |
| `Address already in use` / порт занят | Укажите другой порт в `ui.run(..., port=8081)` |
| Страница пустая или не обновляется | Обновите страницу (`Ctrl+F5`), проверьте, что процесс в терминале запущен |
| Нужно начать с чистого листа | Остановите приложение и удалите `assemblies.db` |
| `Не найден файл ключа «credentials.json»` | Скачайте JSON-ключ сервисного аккаунта и положите его рядом с `app.py` (см. «Экспорт в Google Таблицы») |
| Ошибка `SpreadsheetNotFound` или «доступ запрещён» | Проверьте, что в Google Cloud включены **Sheets API** и **Drive API**, и что ключ скачан из того же проекта |
